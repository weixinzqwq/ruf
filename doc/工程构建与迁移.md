## 构建与回归

在`D:\game\aola_ruffle`打开PowerShell：

```powershell
& .\src\tools\build.ps1 -Component optimization -Action metadata
& .\src\tools\build.ps1 -Component optimization -Action test
& .\src\tools\build.ps1 -Component optimization -Action build
& .\src\tools\build.ps1 -Component launcher -Action build
```

全部Cargo操作使用`--locked --offline`，从本目录依赖解析，不从旧工程取文件。两条源码使用独立target，减少互相等待和重编译。build默认生成新时间戳目录，拒绝覆盖已有目录；源码内诊断build标记需在真正发布新轮次前同步更新，输出目录名不代表优化内容自动变化。

系统前提仍为Windows x64、Microsoft C++构建工具/Windows SDK、已安装WebView2运行时；日志工具需要Python 3。这些是系统软件，不复制安装目录。Rust、Java和FFDec项目侧分发文件已收拢。编译缓存可达十余GiB，完整构建前应预留足够磁盘空间；本次未迁入约14GiB旧共享构建缓存。

启动桥重建使用`src/tools/build-launcher-bridge.ps1`，会校验导出类、行为标记和非代码tag，再更新桥候选及离线mock。不会登录或向游戏发包；更新桥后需要另行重编登录器以嵌入新资源。

## 采集分析

```powershell
python .\src\tools\analyze-performance.py --b "<B日志或diagnostics目录>" --output .\doc\evidence\latest-summary.json
python .\src\tools\analyze-performance.py --a "<A日志或目录>" --b "<B日志或目录>" --output .\doc\evidence\latest-ab.json
```

工具只读取日志并汇总，不自动断言因果。目录参数选择最近修改的performance日志；报告记录实际路径、哈希、版本、开关、窗口、响应数和结束标记。对照必须核实相同地图、顺序和窗口；旧历史脚本保存在压缩归档内，其绝对路径属于当时环境，不作为当前可执行入口。
