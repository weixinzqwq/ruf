## 构建与回归

在`D:\game\aola_ruffle`打开PowerShell：

```powershell
& .\src\tools\build.ps1 -Component optimization -Action metadata
& .\src\tools\build.ps1 -Component optimization -Action test
& .\src\tools\build.ps1 -Component optimization -Action build
& .\src\tools\build.ps1 -Component launcher -Action build
```

全部Cargo操作使用`--locked --offline`，从本目录依赖解析，不从旧工程取文件。两条源码使用独立target，减少互相等待和重编译。build默认生成新时间戳目录，拒绝覆盖已有目录；源码内诊断build标记需在真正发布新轮次前同步更新，输出目录名不代表优化内容自动变化。

系统前提仍为Windows x64、Microsoft C++构建工具/Windows SDK、已安装WebView2运行时；日志工具需要Python 3。这些是系统软件，不复制安装目录。Rust、Java和FFDec项目侧分发文件已收拢。编译缓存可达十余GiB，完整构建前应预留足够磁盘空间；本次未迁入约14GiB旧共享构建缓存。

启动桥重建使用`src/tools/build-launcher-bridge.ps1`，会校验导出类、行为标记和非代码tag，再更新桥候选及离线mock。不会登录或向游戏发包；更新桥后需要另行重编登录器以嵌入新资源。

## 采集分析

```powershell
python .\src\tools\analyze-performance.py --b "<B日志或diagnostics目录>" --output .\doc\evidence\latest-summary.json
python .\src\tools\analyze-performance.py --a "<A日志或目录>" --b "<B日志或目录>" --output .\doc\evidence\latest-ab.json
```

工具只读取日志并汇总，不自动断言因果。目录参数选择最近修改的performance日志；报告记录实际路径、哈希、版本、开关、窗口、响应数和结束标记。对照必须核实相同地图、顺序和窗口；旧历史脚本保存在压缩归档内，其绝对路径属于当时环境，不作为当前可执行入口。

## SWF 生命周期实验

以下入口使用优化源码线及其离线依赖。从项目根目录在 PowerShell 执行。当前构建读取已归档的实收文件 `resources/swf-reference/lifecycle/2026111953323155/newpetpackage~2026111953323155.swf`。观测还使用 `resources/original` 中的 interfaces、util 和 common。历史归档 ZIP 仅用于第一版记录及跨版本对照。[背包视图切换试点](SWF生命周期试点.md)

```powershell
# 在新目录生成带采集、官方回退以及各组入口的 Windows 实验包
& .\src\tools\build.ps1 -Component optimization -Action swf-build

# 运行定向 navigator 回归并取得本次构建的 headless runner 路径
$runner = & .\src\tools\build.ps1 -Component optimization -Action swf-test
python .\src\tools\swf-patches\observe_skin_motion.py --runner $runner
```

两个入口都支持 `-RoundtripDirectory` 复用已有的原样回写目录。运行候选的局部关闭实验时，先执行 `python .\src\tools\swf-patches\patch_skin.py`，再给观测脚本添加 `--candidate <输出的 candidate.swf>`。运行无改动回写控制时使用 `--control <回写目录\run-1\control.swf>`。每次观测使用独立目录，结果保存在 `doc/evidence/swf-lifecycle/harness-*/report.json`。

本次实收版本的试验包位于 `dist/aola-swf-lifecycle-20261121-current`，构建标记为 `swf-lifecycle-pilot-v2`。原件、回写、功能候选共用同一 EXE 和四种操作返回记录。首版保存在 `dist/aola-swf-lifecycle-20261121`，其中的 `capture-21269-6015` 是本次官方原件的来源。[当前版实机操作](SWF生命周期试点.md#当前版的实机操作)

可用 `python src/tools/swf-patches/inspect_run.py <运行目录>` 对单轮实测作只读复核。它从退出后生成的资源报告和该轮唯一的性能日志读取数据，按播放器代次和窗口设置划分采样区间，汇总完整 GC 后的全局资源盘点。首版没有动作记录时该字段留空。[本次登录的逐段结果](evidence/swf-lifecycle/live-capture-20261121/performance-scope.json)

HTTP 回环端到端用例可单独执行 `& .\src\tools\build.ps1 -Action swf-loopback`。本次环境拒绝连接本机 `127.0.0.1`，独立 TCP 探针也返回 Windows 10013，因此 HTTP 回环用例没有通过验收。离线 navigator 回归与正式游戏实收各自记录结果。

## 亚比切换性能实验

在项目根目录执行 `& .\src\tools\build.ps1 -Component optimization -Action pet-switch-build` 可生成独立 Windows 实验包。两组都使用同一份实收背包原件和 util，并校验当前官方响应。A 和 B 采用轻量详情计时，只在最外层详情派发上记录耗时、入口和所处阶段，避免为每次属性读取计时。两组唯一的引擎差异是 B 启用嵌套 goto 中无父 MovieClip 子树的叶节点优化。深度定位入口启用同一项优化，另记录阶段计数、命中数和每个响应结束后的无父对象抽样。[实机定位记录](背包详情与SWF去重.md#切换亚比时的实机停顿)

两组各在固定地图与窗口打开背包，静置 6 秒后按相同顺序和节奏切换约 8 次，再正常退出。`runs` 下每次单独保存结果，`compare-A-B.cmd` 重读两份原始采集，按详情入口、阶段和窗口分组列出每次耗时。首次网络派发与已缓存的详情派发分别比较。深度定位记录在详情处理结束后抽样至多 256 个弱引用槽，最多保留 16 个分组；抽样成本单列，记录的是无父根的类型和资源来源，不能据此判断谁还持有强引用。

## AolaFlux 参考优化实验包

在项目根目录执行 `& .\src\tools\build.ps1 -Component optimization -Action flux-build`。默认写入新的时间戳目录，可用 `-OutputDirectory` 指定新的绝对路径。下列两份原件已在本机备齐，资源目录沿用项目既有的本地归档约定。

| 源文件 | 在发行包内的位置 | 用途 |
| --- | --- | --- |
| `resources/swf-reference/notice/2026062579184482/messagesendservice~2026062579184482.swf` | `swf-notice/original.swf` | 匹配当前公告响应，重建六处公告编辑 |
| `resources/original/petfightnew~261112849126071.swf` | `swf-battle/original.swf` | 匹配战斗资源，重建指定攻击演出的提前返回路径 |

若改动这两个补丁，先按「SWF 生命周期实验」的 `swf-test` 命令取得本次构建的 `$runner`。以下命令在独立目录中重建并执行两个行为回归，结果分别保存在测试目录的 `runner.log`。

```powershell
$trial = Join-Path $PWD ("build\flux-swf-" + [Guid]::NewGuid().ToString("N"))
python src/tools/swf-patches/patch_notice.py --output-dir "$trial\notice"
python src/tools/swf-patches/patch_battle.py --output-dir "$trial\battle"
python src/tools/swf-patches/test_notice_patch.py --runner $runner --candidate "$trial\notice\swf-notice\messagesendservice-notice.swf" --work "$trial\notice-run"

```
