# 回收与纹理复用

## 目标与实现

解决回收周期长期停在标记阶段，以及动画尺寸细微变化导致临时画布频繁重建的问题。

- 回收：标记队列和待扫描根已清空时，在有界工作返回前转入清扫。不强行完成整轮GC，不增加原切片预算。
- 纹理：局部混合画布宽高向上按16像素归档，保留原点和像素比例，新增区域清空；临时纹理空闲池预算256 MiB。
- 源码入口：`src/optimization/engine/core/aoqi-gc-arena`、`core/src/player.rs`、`render/wgpu/src`。前缀均相对于优化引擎根。

## 测试进度与结果

2026-11-05 A为回收推进版，B增加画布尺寸复用。用户实际采集的是第二战，反馈两版都流畅；窗口和时序存在差异，不能当作严格同场景帧率因果实验。

对齐区间两版各完成4个回收周期，退出时均到18；对象内容销毁与分配释放均有实际计数，满足累计创建减累计释放等于当前分配。未复现此前周期停在6的问题。当前分配不等于泄漏对象数量。

| 资源指标 | A | B |
| --- | ---: | ---: |
| 纹理池命中率 | 53.59% | 67.84% |
| 新建纹理/次绘制 | 13.23 | 9.14 |
| 压力淘汰/次绘制 | 9.68 | 5.63 |
| 查找耗时/次绘制 | 0.85ms | 0.58ms |

纹理新建减少30.89%，归档实际命中93.61%的混合目标，额外补边约3.21%。支持资源复用有效，不代表发光算法或整个游戏有同等提速。

## 后续操作与验收

11 月 22 日的 AolaFlux 对照确认本项目已有 384 MiB 显示位图缓存预算和 256 MiB 临时纹理池预算。新的池维护按帧检查到期桶，复用过的桶重新排期，默认到期时间仍为 120 帧。动态下调预算时只回收到所需额度，借出的纹理仍由调用方持有。DX12 合成尺寸循环中，96 MiB 预算发生 120 次热纹理重建，256 MiB 下为 0，因此沿用项目默认值。[移植与验收](AolaFlux对照与移植.md)

1. 使用保留的子树测试包A入口作为当前行为基准，手动登录固定地图。
2. 固定窗口、画质、亚比和战斗流程，重复短测与长测；不要与早期不同窗口的FPS直接相减。
3. 核对`gc.completedCycles`持续增长、`lifetimeAllocated-lifetimeFreed=allocations`、完整周期后的数量基线，以及纹理请求密度、新建/绘制与池命中率。
4. 若完整周期持续完成但基线仍上升，再查实际持有者；不通过强制清空仍在使用的模型、类或监听器制造下降。
