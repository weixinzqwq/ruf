### 战斗选招帧率

「功能面板 → 表现 → 游戏表现」中的「选技能时恢复原版帧率（防回合倒计时过快）」默认开启，点选时立即生效，设置保存在 `aola-data/mypro/display.json`。旧设置文件保留已有选项，新开关默认开启。

实收战斗 SWF 的 `FightPanel.countDown` 调用 `CountMovie.startCount` 后打开选招。`CountMovie` 用时间轴最后一帧的 `onOneLoop` 推进倒计时，`FightFrameRateManager` 的默认值是 25 FPS。

AVM2 加载 ABC 时按 `mmo.petfightnew.common.FightPanel` 的类和方法名绑定。原生无参 `enableClick()` 成功返回后进入选招等待，带布尔参数的版本使用传入值。`disableClick`、构造和退场用于恢复基准帧率，回放初始化按基准继续播放。设置开启时，等待选招且基准高于 25 FPS 才限制到 25 FPS；设置关闭或使用原生自动战斗时沿用基准。宿主直接使用原生自动按钮回执，选招期间每 250 毫秒也读取一次游戏内按钮的实际状态。面板显示和保存用户选定的基准帧率，玩家可在等待中改速，离开等待后应用新的基准。[AVM2 绑定](../src/optimization/engine/core/src/avm2/swf_operation.rs) · [桌面设置](../src/optimization/engine/desktop/src/mypro_features.rs)

Core 221 项、桌面 132 项、前端 182 项回归通过，12 项按原套件标记忽略。两份实收战斗 SWF 通过名称绑定核对，离线 Edge 验证了开关默认值、即时修改和回读。发行版 Core 和桌面 EXE 分别通过 15 个 AVM2 夹具检查点，覆盖 `Stage.frameRate` 的 120 → 25 → 120、回放、错误返回、构造和退场。实服倒计时仍需用登录后的战斗实测。[Core 回归](../build/battle-input-fps-core-test.log) · [面板回归](../build/battle-input-fps-panel-edge.log) · [桌面 EXE 运行记录](../build/battle-input-fps-fixture/desktop-dynamic.stdout.log)

### 离线适配新的战斗 SWF

准备带官方数字版本名的 `petfightnew~<版本号>.swf`。仓库根目录运行以下命令，替换路径及版本号，输出目录须为新目录。

```powershell
python src/tools/swf-patches/patch_mypro_battle.py --weekly-source 'D:\新原件\petfightnew~123456.swf' --output-dir 'build/weekly-123456'
```

会生成新版叠加后的战斗文件和 `aola_battle_profile.rs`，同时核对既有优化、模型选择器、浮字与演出、背景和原生按钮的生产方法及重建结果。要用于随后的打包，在同一命令中追加 `--install-weekly`，选择另一空输出目录。安装步骤在验证完成后归档原件并切换本地构建配置，再用以下命令生成播放器。若新版更换了受检方法、指令结构或压缩格式，先根据生成日志调整对应补丁；旧配置可继续构建。运行时按官方域名、版本和完整原件字节核对后才选用候选，缺失或不匹配时继续使用可用的原资源。

```powershell
.\src\tools\build.ps1 -Component optimization -Action flux-build -MyProTools -OutputDirectory 'dist/aola-t3-123456'
```

离线演练使用同内容、不同数字版本名的官方原件。独立重放 26 项基础修改和 85 项表现与模型修改，分别与 6,574,345 字节基线、6,585,856 字节成品完全一致。成品保留全部非 ABC 标签。非数字版本名和截断原件均被拒绝。实际新周官方文件仍需单独运行上述验证。

### 周更资源回退

`petfightnew`、`newpetpackage`、`messagesendservice`、`controlv2` 和 `start` 的版本化官方 GET 响应先检查外置清单。请求路径、版本及官方响应 SHA-256 匹配时，播放器校验候选的 SHA-256 和 FWS 结构后使用候选。随后可按既有版本使用内置配方。较新的官方资源回退原版时，「概览」会显示受影响的资源和版本。

活动面板、换宠和背包观测在加载 ABC 时按包、类和方法名绑定，活动入口还校验静态六参数签名。这些钩子无需随方法编号更新。外置补丁的生成命令和失败报告详见[周更 SWF 同步](工程构建与迁移.md#周更-swf-同步)。

同一个成品 EXE 使用同一个离线官方缓存跑完五组启动。有效清单命中外置候选，缺清单、官方摘要不符、版本过旧或候选摘要不符时均播放原版并记录版本漂移。概览横幅单独通过离线 Edge 的显示和清除回归。[桌面验证](../build/weekly-sync-runtime-release.log) · [概览回归](../build/weekly-sync-panel-edge.log)

## 使用形态规则

1. 在「功能面板 → 形态」底部填入对应通道的素材 ID。种族号、皮肤号和战斗素材号可能不同。背包展示优先按原展示 ID 查海报规则，也兼容以原皮肤 ID 为源的海报规则。
2. 点击「加入列表」，勾选「启用形态规则」并「保存规则」。多个通道的原 ID 不同时分别建规则。也可导入旧版规则数组或含 `skins` 的对象。
3. 游戏按官方路径与优先级请求各片。敌方主体开关控制朝向 1，己方对应朝向 2。背包与进战头像共用一条规则，优先使用战斗目标，留空时使用背包目标。
4. 「恢复官方」关闭映射并保留规则。背包打开时刷新当前展示，战斗内保留入场时的规则，退场后应用最新修订。

## HTTP 形态替换

规则文件仍为 `aola-data/mypro/morph.json`，修订和旧版字段保持原格式。后台写盘成功后发布只读快照，战斗入场和退场更新独立战斗快照。配置发布无网络调用。[规则实现](../src/optimization/engine/desktop/src/mypro_features/morph.rs)

官方资源写入 `cache/v1/`，改写成品写入独立的 `cache/morph-adapted/`，两者共用 `AOLA_DISK_CACHE_BUDGET_MB` 的 LRU 预算。成品键包含原 ID、目标 ID、通道分片和目标版本。命中成品时从盘读取；冷请求复用官方目标缓存，按全局两个许可解压和改写。引擎在结构化解析后仅修改 `SymbolClass` 和 ABC 字符串池，原样交付其他 Tag。拦截故障会在启动诊断中记录 `morph-http` 并重走原 URL。[拦截](../src/optimization/engine/frontend-utils/src/backends/navigator/aola_morph_intercept.rs) · [改写](../src/optimization/engine/frontend-utils/src/backends/navigator/aola_morph_transform.rs)

目标版本从游戏正常加载的官方版本目录解析。本地反编译的 `VersManager.getVersion` 在版本目录已初始化、条目未单独标版时使用 `1210`，代码沿用这个默认值。版本目录无法解析、无法安全确定路径或分片处理失败时走官方原请求。两个样本 ID 同属当前游戏的四片背包、每个朝向三片战斗布局。游戏继续按原 ID 选择缩放等展示参数，因此高清素材在真实背景和站位中的显示还需实测。

登录 Cookie 与形态静态资源分开处理。`navigator.rs` 按公开路径捕获版本目录和选择形态资源。版本化模型和 `versiondata` 的缓存未命中时，使用沿用播放器代理配置的匿名客户端。目标 SWF 冷下载复用这个客户端，HTTP 请求不携带登录 Cookie。显式认证请求继续走原有会话路径。

### 背包展示皮肤映射

`aolaMyProVisualSkinId` 优先返回规则的海报目标。海报留空时，背包用原生 `PetSkinDataService.getPetSkinInfoBySkinId` 查背包目标，宿主复核已确认的 ID 是否仍为当前背包目标。表中没有对应目标、规则未命中或已关闭时使用游戏原皮肤 ID。映射用于展示，原亚比的个体 ID、穿戴状态和原生操作参数沿用真实数据。[宿主查询](../src/optimization/engine/desktop/src/aola_host.rs) · [背包展示补丁](../src/tools/swf-patches/MyProBackpackVisualPatch.java)

非战斗状态收到新修订时，宿主通知打开的背包清理 `PET_VIEW_DOMAIN` 并刷新当前详情和已有头像。切换亚比和关闭面板时回收上一展示的背景、粒子及语音，过期加载回调按展示代数丢弃。战斗使用进入时冻结的头像映射，退场后背包应用待处理修订。

普通语音使用皮肤表的 `talkRes` 和游戏版本查询，背包持有这一播放通道，便于切换或关闭时停止。特殊解锁语音保留真实皮肤对应的原生活动入口，映射目标的特殊活动按钮不显示。

### 背包高清比例补偿

两版 `newpetpackage` 在 `PetBigIconDetail.afterOtherOperate` 给原生 `PetIconHandler.setIcon` 增加完成回调。游戏完成模型缩放和位置对齐后，回调通过 `aolaMyProBackpackTarget(sourceId)` 读取启用的背包规则。它用原生 `PetIconConfig.getPetMovieHDScale` 计算目标比例除以源比例，并把结果乘到模型包装对象的两个轴上。外层详情容器和模型的平移保持游戏原值，同一挂载只执行一次。未配置映射时，查询返回 `0`。[宿主查询](../src/optimization/engine/desktop/src/aola_host.rs) · [背包补丁](../src/tools/swf-patches/MyProBackpackPatch.java)

展示皮肤映射接入后，模型加载仍由 `afterOtherOperate` 用原 `viewId` 请求，游戏按原 ID 应用高清比例。补偿仍在挂载结束后执行一次。

比例补偿依据加载完成时的规则快照。网络层回退到源素材时，规则仍可能命中，加载回调可能按目标比例缩放回退素材。
