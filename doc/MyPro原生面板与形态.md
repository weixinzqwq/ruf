# MyPro 原生面板与亚比形态

## 播放基线与接入位置

本轮从 `src/optimization` 的实际工作树构建。仓库 HEAD 为 `ab6a544952e64a9c0ac5fe5b05810b069bf0f806`，工作树还包含已通过实战验证的换宠优化。参考包为 `dist/aola-battle-glow-reuse-20261125`。PID 31300 在 1200×700 下完成三场战斗，最低换宠窗口为 21.91 FPS，第二场第三次换宠后的两个完整窗口为 40.79、51.23 FPS。[实战记录](回收与纹理复用.md#发光复用包三场实战)

| 部件 | 所有者与职责 |
| --- | --- |
| 原生窗口和 Player | `desktop/src/app.rs` 的 winit 事件循环创建游戏窗口；`desktop/src/player.rs` 继续组装原 Player、输入、音频、存储和渲染后端。使用本地锁定的 Ruffle 0.8.0-nightly.2026.10.17、winit 0.30.13、wgpu 30.0.1、egui 0.36.2 |
| 播放器与功能面板 | `desktop/src/mypro_host.rs` 建播放器主窗，上方的「功能面板」按钮打开第二个 Windows 顶层窗口，下方嵌入原生游戏窗口。独立功能窗使用 Wry 0.53.5 和 WebView2，官方登录 WebView 继续由 `aola_host.rs` 管理 |
| 游戏调用和资源 | `AolaInterface::call_method` 处理展示查询，游戏资源由 `frontend-utils/src/backends/navigator.rs` 读取。观察、资源内容替换和游戏原有加载是三个独立步骤 |
| 游戏与面板寿命 | 工具页的每次加载有自己的代数，Player 有独立会话标识。设置、形态和记录的文件操作在后台执行。关窗时先释放引用游戏子窗的 surface，再释放父窗 |

入口 `AOLA_MYPRO_TOOLS` 选择是否加载工具。两种入口均沿用固定 60 FPS、战中 GC、弱键回收、无父对象优化、发光融合、纹理池、发光写回、换宠分段计时和分段退出计时。普通播放器使用原来的启动路径。现有实战参数和本轮窗口代码见[包生成器](../src/tools/swf-patches/flux_package.py)与[原生宿主](../src/optimization/engine/desktop/src/mypro_host.rs)。

游戏区默认使用 1200×700 物理像素。工具窗可以单独移动、调整尺寸、最小化或关闭，其位置不参与游戏视口计算。系统 DPI 用于原生控件布局；按用户要求，百分比缩放控件不列入开发范围。

## 工具合同和数据来源

工具页向宿主发送 `protocolVersion`、`bridgeGeneration`、`requestId`、`sessionId`、`command` 和 `payload`。宿主处理具名命令并使用固定回调返回结果。页面刷新重新获取快照。切换游戏会话时清除采集视图和战况，旧请求不能修改新会话。[本地工具页](../src/optimization/engine/desktop/src/mypro_panel/index.html)

| 能力 | 来源与边界 |
| --- | --- |
| 暂停、继续、显示或隐藏工具窗 | 暂停和继续操作当前 Player。关闭工具窗只隐藏该窗，主窗工具栏按钮可再次调出 |
| 资源与面板调用 | 资源请求取自 navigator。`Panel_Helper.loadResAndShow` 的调用记录同时保留 URL 与类名。记录带来源和序号，入环形缓冲后可分页、导出及只读导入 |
| 战况 | 已核验的战斗进入、退出和换宠方法。可显示场次和换宠次数；血量、技能和装备没有接入的数据源 |
| 表现 | 公告、万域之潮出招、五类变身立绘和战斗背景使用原有受版本约束的资源钩子；设置应用于后续相应的表现调用 |
| 亚比形态 | 五字段规则支持素材 ID、三个独立目标和备注。持久化、战斗绑定版本、当前游戏查询结果分别记录。战中保存或恢复官方时，本场继续使用入场时的规则 |

形态规则以原始素材键查一次。主体按游戏传入的朝向区分我方和对方，战斗头像独立查表。缺目标或目标未准备好时，原函数继续使用官方素材。面板的命中数表示游戏选用了一个经检查的显示键；实际画面由游戏原加载器绘制。具体可用通道以当前会话的已识别显示入口为准。[规则与版本实现](../src/optimization/engine/desktop/src/mypro_features/morph.rs)

## 使用形态规则

1. 用[播放器入口](../dist/aola-mypro-window-20261125/run-game.cmd)进入游戏。在背包中看一次原亚比与目标亚比，或在战斗中让两只亚比显示一次。点击主窗上方的「功能面板」，在独立窗口中打开「形态 → 最近的素材 ID」，按「背包模型」「战斗主体」「战斗头像」读取各自的官方键。种族号、皮肤号和最终战斗素材号可能不同。
2. 在「新增规则」中填原素材 ID，以及相应的背包或战斗目标 ID。若两个通道的原键不同，分别建两条。点击「加入列表」，勾选「启用形态规则」，点击「保存规则」。面板支持粘贴旧版规则数组或含 `skins` 数组的 JSON。
3. 重新打开该亚比的详情，或让它在下一场战斗上场。未准备好的目标本次显示官方素材，由原游戏的资源调度器在后台准备，下一次显示时重查。可以对照「最近的素材 ID」中的原键、目标键和命中状态。「作用敌方主体」只控制敌方的场上模型，双方头像都使用战斗目标键。
4. 「恢复官方」关闭映射并保留规则。背包在下次显示时使用新设置；已开打的一场使用入场时的战斗版本，到下一场才切换。F8 切换工具窗。使用[纯播放器入口](../dist/aola-mypro-window-20261125/run-player-only.cmd)可用同一个 EXE 对照；两种入口共用这个新包的数据目录。

在双窗初版的 PID 120684 中，战斗和背包都载入了对应的形态补丁。规则在 23:25:34 保存为启用，随后在 23:26:05、23:27:20 和 23:29:28 开战。界面上的两条「5336 → 6044」说明源键已命中。该版只向宿主传一个就绪布尔值，没有记录分片进度、失败原因或 HTTP 结果。本地游戏图鉴将 6044 登记为「万澜梦星海-银河」，可穿戴种族列表包含 5336。[初版启动日志](../dist/aola-mypro-window-20261125/aola-data/diagnostics/startup-1795620179934-120684.jsonl)

| 显示入口 | 原因与修复 |
| --- | --- |
| 己方战斗主体 | 官方 `FightResConfig` 将 6044 的每个朝向拆为三片。`PetAssetsLoader` 加载主片；`PreloadListManager.preloadComplementaryMovieFile` 按游戏原宠 ID 补其余两片。初版在替换时只对目标预取第 0 片，完整性检查又要求所有帧已就绪。修复后冷启动按所需朝向为目标取齐三片；有主配置但缺帧时也会补取目标的后两片。[战斗助手](../src/tools/swf-patches/MyProBattleModel.as) |

## 独立窗口实测

最终包在 Windows 单屏、系统 DPI 120 下运行本地影片。PID 140132 启动时只显示播放器主窗，客户区 1200×745，其中原生工具栏 45 像素、游戏区 1200×700。点击按钮后出现 850×725 的独立工具窗。移动工具窗、最小化、点 ×、再从主窗按钮或 F8 调出，游戏视口的物理位置和尺寸一致。最小化和点 × 后各观测了一个完整五秒区间，游戏分别以 60.04、59.98 逻辑 FPS 继续推进。八次采样均为同一影片代数。暂停／继续、中文输入、刷新工具页和防止旧页面操作新会话也通过。[验收数据](evidence/mypro-tools-20261125/offline-acceptance.json)

PID 59964 使用两个可区分的本地示例素材，从游戏子窗读取到「官方红色 → 目标 29 蓝色 → 缺失目标 87 回退红色 → 目标 29 蓝色 → 恢复官方红色」。采样点每次都属于当前进程的游戏窗口。真实亚比的显示与服务器素材可达性要在游戏中确认。[最终功能窗截图](evidence/mypro-tools-20261125/morph-panel.png)

性能采集结束后，可用本包的 [measure-game-close.ps1](../dist/aola-mypro-window-20261125/measure-game-close.ps1) 退出并写入同 PID 的最终性能记录。已验证功能窗置前时仍会关闭正确的游戏进程。[双窗关窗验收](游戏关闭耗时.md#独立功能窗的关窗入口)

另在 1200×700 下交错执行同一段 100 帧固定发光影片，每种模式两次。六轮均重绘 3,800 个缓存表面，执行 5,500 次融合发光、7,700 次模糊和 1,700 次直接写回；六轮的战中 GC 追赶开关均开启。旧包按原离线方法直接播放同一影片，新包两组都使用真实游戏宿主。两次耗时有波动，这组六次样本不能给出实战帧率或稳定的窗口开销。
