# goto与子树遍历

## 战斗中无父对象为什么仍会运行

AS3 的 `parent` 表示当前显示容器。脚本可以用数组保存已离开容器的影片，继续让它播放、调用 `gotoAndStop`，随后再用 `addChild` 挂回。这个过程会影响画面和脚本顺序。播放器为这些影片单独安排帧阶段。正常帧依次推进、构造、处理帧脚本，较新版 AS3 影片的嵌套跳帧还会再调度构造和脚本阶段。[调度源码](../src/optimization/engine/core/src/frame_lifecycle.rs) · [保留引用后跳到第三帧的参考输出](../src/optimization/engine/tests/tests/swfs/avm2/goto_on_orphan/output.txt)

无父登记表只保存弱引用。其他强引用全部消失后，GC 可以回收该对象。对象之间形成的孤立引用环也符合条件。标记尚未完成时，登记表中仍可能读到对象。重新挂回显示树后，对象改由父节点调度。仅由时间轴移除、未经脚本移动的影片，还允许在该帧运行最后的脚本，随后从无父登记表移除。计数 `orphanSlots` 包括尚待检查的槽，无法逐个说明游戏中谁仍持有该对象。[无父登记与清理](../src/optimization/engine/core/src/orphan_manager.rs)

用弱键战斗包单独运行了 64 个两帧动画。每个都先挂上舞台再移除，当 `parent` 与 `stage` 都为空时才计入离台调用。前 12 帧保留两组各 32 个对象，每组各运行 352 次离台帧脚本、收到 384 次离台广播。随后释放其中一组的外部强引用，在第 20 帧采样时其弱键已全部消失，接下来 20 帧内这组的两类回调均为零。保留组仍有 32 个弱键，其中一个挂回舞台后又运行了 20 次帧脚本。影片在第 13 帧起制造了普通对象分配负载，使用播放器自身的 GC 调度。实战等待回收的帧数会随负载而变。[测试影片源码](../build/battle-orphans-20261124/lifetime/Lifetime.as) · [发行版实测](../build/battle-orphans-20261124/lifetime/run-6v2is2fe/summary.json)

仅构造和脚本遍历就占 4.132 秒。引擎检查了 4,137,098 个槽次，其中 2,367,103 次进入对象阶段处理，1,769,433 次因休眠跳过，562 次发现对象已失效或重新挂载。同一槽会反复出现。整个帧管线只记录了 3 次实际调用 AS3 帧脚本。事件监听器另行计数。该窗口的 GC 切片共用 60.9 ms。[同 PID 性能日志](../dist/aola-weak-battle-20261124/aola-data/diagnostics/performance-1795497102430083400-118488.jsonl)

### 战斗跳帧测试包

候选在嵌套跳帧时仍检查无父根是否存活、是否已经重新挂载。对完整载入且已构建的 AS3 MovieClip，如果整棵树都没有注册帧脚本、等待执行的脚本或跳帧、循环复位或未完成的构造，并且所有后代都在支持范围内，引擎会记下这个结果。再次跳帧时可以跳过该根的构造和脚本遍历，即使它正在播放。正常帧仍推进播放，广播仍按原顺序送达。注册脚本、添加子对象、改换父节点等操作会使结果失效。包含按钮、Loader 等对象的树交由已有逻辑处理。[无父子树判断](../src/optimization/engine/core/src/orphan_manager.rs) · [MovieClip 条件](../src/optimization/engine/core/src/display_object/movie_clip.rs)

### 普通帧无父对象的调度与实战采样

普通帧需要主动调度舞台树以外的影片。例如战斗管理器可以在数组里保留一个已 `removeChild` 的特效，再读它的 `currentFrame`、等待帧脚本或把它加回场景。引擎的无父列表只存弱引用。每个阶段先检查对象是否还存在且没有父对象。AS3 创建或移出舞台的影片可以继续走帧，直到重新挂载或被 GC 回收。由时间轴的 `RemoveObject` 移除且未被 AS3 接管的影片，可完成当帧最后一次脚本，随后从无父列表移除。[无父列表和清理时机](../src/optimization/engine/core/src/orphan_manager.rs)

| 普通帧遇到的对象 | 战斗中的处理 |
| --- | --- |
| 根或后代的时间轴还在播放 | 继续推进帧号和处理时间轴指令。根停止而子影片仍在播放时，子影片同样得到推进。 |
| 活动根下有已停止的稳定子树 | 在推进阶段跳过已确认静止的分支。播放、跳帧、挂载等状态变化会撤销相关缓存。 |
| 时间轴仍在播放，整棵树都已构造且无登记脚本、待办构造或跳转 | 保留时间轴推进，在当帧构造和脚本阶段跳过整棵树的重复递归。 |
| 有待执行的帧脚本、首次构造，或暂时无法判断 | 按原顺序处理。播放中仅在未来帧登记脚本的树也保守处理。按钮、加载器等继续走各自的生命周期。 |

默认入口把 `AOLA_ORDINARY_ORPHANS` 设为 `battle`，在识别到战斗后生效，退出战斗后恢复。单项对照设为 `0`；直接启动 EXE 且未设置这个变量时也关闭。两种入口均可记录采样。遍历省下的时间与 GC 释放的节点数分别计量。[影片的休眠条件、唤醒与逐帧处理](../src/optimization/engine/core/src/display_object/movie_clip.rs)

读同一 PID 的 `performance-*.jsonl` 时，用 `performanceInterval.frameUpdate.ordinaryOrphans` 查看整个区间内 `enter`、`construct`、`scripts` 三个阶段。各阶段的 `invalidRoots`、`sleepingRoots`、`scriptlessRoots`、`dispatchedRoots` 分别是失效／已有父对象、整树静止、整树已构造且无脚本、实际进入该阶段的根访问次数。同一对象可在多帧和多个阶段反复出现。`enter.sleepingDescendants` 是直接跳过的子树入口次数。`directFrameScriptCalls` 是普通帧无父脚本阶段真正调用的 AS3 帧脚本次数，包含后代；全局事件和嵌套跳帧另行调度。

每次周期采样还会预约下一次普通帧。`ordinaryOrphanSample` 描述该帧推进前等距抽取的至多 256 个弱槽，列出数量最多的 16 组，包括实际声明类、资源类别、影片内符号、根的播放状态、是否有子对象、当前帧和待执行脚本标记。用 `playing-multiple-frames` 找标记为播放中的多帧根，`playing-single-or-empty` 表示根至多只有一帧。停止的根仍可能挂着正在播放的子影片。根的两个脚本标记只描述采样当时的根，后代和未来帧仍可能有脚本。资源为 `unknown` 时不能仅凭符号编号跨影片认定同一对象。[采样实现](../src/optimization/engine/core/src/orphan_census.rs)

同一采样帧的 `frameScriptReceivers` 记录该帧无父脚本遍历中真正接收调用的实例声明类，包括抽样根以外的根和子孙。`directCalls` 是该帧实际调用数；前 256 次调用最多登记 16 个接收类，多出的调用计入 `omittedCalls`。`classes[].calls` 按调用累计，无法据此反推出有多少个独立实例。同一个接收类可能出现在多个无父根下面。[调用点与阶段范围](../src/optimization/engine/core/src/frame_profile.rs)

## 定位结果

原版 MyPro PID 142192 两次有协议结算的战中，无父对象快照最高为 935 和 827，补清后分别回到 297 和 298。与之对照，v2 同为小窗的最慢连续两段共 10.640 秒，无父构造和脚本遍历合计 3.305 秒。MyPro 只有无父存量和按类新建的计数，尚不能算出两版每次跳帧的无父遍历差额。[实战明细与耗时口径](MyPro实战采集.md#11-月-24-日-16-时实战)

同片对照发现，MyPro 默认在 37 次嵌套跳帧内额外广播构造完成事件 0 次，关闭 `AOQI_FAST_GOTO` 后变为 37 次，与 v2 一致。四组在跳帧期间均未新建测试类实例。原版的实战采集入口、无关对象脚本的执行顺序和四对独立进程的耗时见 [MyPro 跳帧实测](MyPro实战采集.md#嵌套跳帧与无父对象)。

原有全局路径中，`gotoAndStop → goto_frame → goto_frame_now → run_inner_goto_frame` 会执行整个舞台与无父对象的构造、脚本遍历和事件处理。同帧跳转也有可观察的副作用。无父指当前没有父容器，隐藏和位于屏外的对象也可能有父容器。

2026-11-09采集9次详情响应，每次约0.70～1.25秒。goto内部舞台构建/脚本遍历占51.98%，orphan构建/脚本遍历46.23%，合计98.20%；清理和实际帧脚本执行占比很小。2153次goto中73.34%为同帧，但这不是可直接消除的耗时比例。

逐响应统计独立于普通帧，`phases[].exclusiveMs`之和等于`outerTotalMs`；`inclusiveMs`包含嵌套重叠，不能再加。访问次数不是唯一对象数，槽位增长也不是泄漏证明。
